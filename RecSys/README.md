# 🎓 Чему я научился — рекомендательные системы и A/B-тестирование

В ходе двух практических проектов курса **«Машинное обучение на больших объёмах данных» (ФПМИ МФТИ, 2026)** я прошёл полный цикл разработки рекомендательной системы: от подготовки пользовательских взаимодействий и обучения моделей коллаборативной фильтрации до интеграции ML-алгоритма в существующий сервис и проверки его эффективности через A/B-тестирование.

В первом проекте основной задачей было улучшение качества ранжирования по **NDCG**, во втором — повышение реальной целевой метрики внутри учебного симулятора: средней продолжительности пользовательской сессии.

---

## 🔷 1. Коллаборативная фильтрация и рекомендательные алгоритмы

Научился реализовывать, настраивать и сравнивать несколько подходов к построению персонализированных рекомендаций.

### EASE — линейная модель Item-to-Item

- Строить матрицу совместных взаимодействий \(X^TX\).
- Применять L2-регуляризацию и вычислять веса линейной модели через обращение матрицы.
- Исключать самосвязи между треками.
- Подбирать коэффициент регуляризации по качеству рекомендаций.

### Item-to-Item KNN

- Рассчитывать похожесть музыкальных треков на основе совместных прослушиваний.
- Нормализовать co-occurrence по популярности треков.
- Ограничивать количество соседей до Top-K.
- Комбинировать локальные item-item зависимости с другими моделями.

### Implicit ALS

- Обучать матричную факторизацию на неявной обратной связи.
- Строить латентные представления пользователей и треков.
- Настраивать количество факторов, регуляризацию и число итераций.
- Использовать confidence weighting для учёта интенсивности взаимодействий.
- Генерировать персонализированные Top-N рекомендации с исключением ранее прослушанных треков.

### User-Based Collaborative Filtering

- Использовать сходство пользовательских историй для рекомендаций.
- Строить контрольную рекомендательную модель.
- Сравнивать User-Based с матричной факторизацией в одинаковых экспериментальных условиях.

**Главный вывод:** разные рекомендательные алгоритмы моделируют разные зависимости. EASE и ItemKNN выявляют связи между объектами, ALS обучает скрытые факторы, а User-Based опирается на сходство пользователей.

## 🔷 2. Подготовка данных и работа с implicit feedback

Научился преобразовывать необработанные пользовательские события в обучающие данные для рекомендательных моделей.

- Загружать и агрегировать взаимодействия формата `user, track, time`.
- Преобразовывать пользовательские и трековые идентификаторы в индексы матрицы.
- Создавать разреженные матрицы `CSR` и `COO` через `scipy.sparse`.
- Применять пороговую бинаризацию взаимодействий.
- Агрегировать повторные прослушивания по паре пользователь–трек.
- Использовать время прослушивания как показатель силы неявной обратной связи.
- Разделять наблюдаемый интерес пользователя и уверенность модели в этом интересе.

В ДЗ №1 использовал бинарную обратную связь с порогом `time > 0.87`. В ДЗ №2 применил взвешенные взаимодействия с сигналом `max(0, listen_time − 0.2)` и коэффициентом confidence `alpha=40`.

**Главный вывод:** способ преобразования пользовательских событий в обучающий сигнал существенно влияет на поведение рекомендательной модели.

## 🔷 3. Ансамбли моделей и оптимизация ранжирования

Научился объединять модели с различными принципами формирования оценок.

В ДЗ №1 последовательно построил ансамбль:

`EASE → EASE + ItemKNN → EASE + ItemKNN + ALS`

Освоил:

- Смешивание скорингов с весовыми коэффициентами.
- Стандартизацию оценок разных моделей перед объединением.
- Подбор параметров `LAM`, `THR`, `ALPHA` и `BETA`.
- Оценку вклада каждой модели в итоговое качество.
- Сравнение отдельных алгоритмов и ансамбля с единым бейзлайном.

**Результат:** улучшил NDCG относительно LightFM с `0.94016` до `0.97082` на приватной части лидерборда.

## 🔷 4. Офлайн-оценка качества рекомендаций

На практике освоил метрику **NDCG (Normalized Discounted Cumulative Gain)** для оценки качества ранжирования.

Научился:

- Сравнивать качество рекомендательных моделей с бейзлайном.
- Учитывать порядок релевантных объектов в рекомендательном списке.
- Проводить последовательные эксперименты с гиперпараметрами.
- Различать результаты на публичной и приватной частях лидерборда.
- Анализировать, насколько добавление новой модели действительно улучшает результат.

В первом проекте итоговый ансамбль достиг:

| Метрика | Результат |
|---|---:|
| LightFM baseline NDCG | 0.94016 |
| Итоговый Public NDCG | 0.97040 |
| Итоговый Private NDCG | **0.97082** |

**Главный вывод:** офлайн-метрики позволяют сравнивать модели до внедрения, но не заменяют проверку их влияния на пользовательское поведение.

## 🔷 5. Интеграция ML в работающий сервис

Во втором проекте перешёл от обучения моделей к интеграции рекомендаций в существующую сервисную архитектуру Botify.

Научился:

- Разбираться в устройстве существующего Flask-приложения.
- Добавлять новую модель, сохраняя совместимость с имеющимся HTTP API.
- Предварительно рассчитывать рекомендации и загружать их в Redis.
- Использовать отдельные логические базы Redis для разных алгоритмов.
- Реализовывать выбор рекомендателя в зависимости от экспериментальной группы.
- Запускать и проверять несколько экземпляров сервиса с Docker Compose.
- Диагностировать проблемы запуска по логам Gunicorn и состоянию Redis.

Для ALS было выделено отдельное хранилище **Redis DB 6**. Модель подключена через существующий механизм `Indexed`, без изменения клиентского API.

**Главный вывод:** разработка ML-модели включает не только обучение, но и её совместимость с существующими сервисами, хранение результатов и надёжную выдачу рекомендаций.

## 🔷 7. A/B-тестирование и статистическая значимость

Научился проверять эффективность рекомендательных алгоритмов не только через офлайн-метрики, но и через экспериментальное сравнение пользовательских показателей.

### Организация эксперимента

- Формировать контрольную и тестовую группы.
- Использовать детерминированное хеширование для закрепления пользователей за группами.
- Настраивать распределение 50/50.
- Сравнивать ML-модель с корректным контролем.
- Проводить тестирование на большом количестве эпизодов симуляции.

### Статистический анализ

- Восстанавливать пользовательские сессии по журналам событий.
- Агрегировать метрики на уровне пользователя.
- Рассчитывать средние значения контрольной и тестовой групп.
- Вычислять абсолютный и относительный эффект.
- Строить 95%-е доверительные интервалы с поправкой Уэлча.
- Определять статистическую значимость по положению доверительного интервала относительно нуля.

### Результаты

| Эксперимент | Изменение `mean_time_per_session` | 95% CI |
|---|---:|---|
| ALS vs User-Based | **+16.50%** | [+13.54%; +19.47%] |
| ALS vs SasRec I2I | **+42.55%** | [+39.10%; +46.00%] |

Оба итоговых эксперимента включали по **30 000 эпизодов** и показали статистически значимое улучшение ALS в условиях учебного симулятора.

**Главный вывод:** рост средней метрики сам по себе ещё не доказывает эффективность алгоритма — необходимо учитывать вариативность данных и статистическую неопределённость результата.
