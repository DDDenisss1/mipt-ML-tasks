## 🛠️ Стек технологий

- **Python 3.x** (основной язык)
- **pandas** (загрузка и обработка CSV, работа с DataFrames)
- **NumPy** (векторизованные операции, нормализация скоринга)
- **scipy.sparse** (разреженные матрицы взаимодействий CSR/COO форматы)
- **implicit ALS** (библиотека для матричной факторизации, Alternating Least Squares)
- **EASE** (Embarrassingly Shallow Autoencoder, реализован вручную через numpy)

---

## 💡 Архитектура решения

Использован **ансамбль трёх моделей коллаборативной фильтрации** с последовательным подбором параметров и нормализацией скоринга.

### 🔹 Шаг 1: Подготовка данных и бинаризация

Из обучающей выборки формируется матрица взаимодействий «пользователь–трек»:
- Применяется порог `THR = 0.87` к полю `time`
- Взаимодействия с `time > THR` считаются положительными
- Строится **бинарная** матрица: повторные взаимодействия одного пользователя с одним треком учитываются как одно событие
- Используется `scipy.sparse.csr_matrix` для экономии памяти

**Почему бинаризация?** Поле `time` интерпретируется как степень уверенности, но для EASE/KNN достаточно знать факт взаимодействия, а не его "силу".

---

### 🔹 Шаг 2: Базовая модель EASE

**EASE (Embarrassingly Shallow Autoencoder)** — линейная модель коллаборативной фильтрации без нейросетей:

**Алгоритм:**
```python
G = X^T @ X                    # матрица Грама (item-item co-occurrence)
G[diag] += LAM                 # L2-регуляризация
P = inv(G)                     # обратная матрица
B = -P / diag(P)               # веса связей между треками
B[diag] = 0                    # убираем самосвязи
```

**Параметры:**
- `LAM = 2400` — сила регуляризации (подбиралась по NDCG)
- `THR = 0.87` — порог для бинаризации
  
**Метрика:** NDCG = 0.96671

**Почему EASE?** Модель быстрая (одно обращение матрицы), интерпретируемая, хорошо работает на implicit feedback без настройки learning rate.

---

### 🔹 Шаг 3: Улучшение через Item–Item KNN
К EASE добавлена модель ближайших соседей треков:

**Алгоритм:**
```python
C = X^T @ X                    # co-occurrence матрица
C[diag] = 0                    # убираем самосвязи
D = diag(1 / sqrt(freq))       # нормализация по частоте треков
W = D @ C @ D                  # нормализованные веса
W[каждый_трек] = top-K соседей # оставляем K=200 сильнейших
```

**Параметры:**

- `K = 200` — количество соседей для каждого трека
- `ALPHA = 0.15` — доля KNN в итоговом скоре

**Ансамбль EASE + KNN:**
```python
final_score = (1 - ALPHA) * ease_score + ALPHA * knn_score
```

**Метрика:** NDCG = 0.96735 (улучшение +0.00064)

**Почему KNN?** Локальные паттерны (похожие треки) дополняют глобальные связи EASE.

---

### 🔹 Шаг 4: Добавление ALS и итоговый ансамбль
Обучается модель **implicit ALS** (Alternating Least Squares) для матричной факторизации:

**Параметры ALS:**
- `FACTORS = 32` — размерность latent space
- `REGULARIZATION = 0.25` — L2-регуляризация
- `ITERATIONS = 120` — количество итераций оптимизации
- `CONFIDENCE = 480.0` — множитель уверенности для implicit feedback
  
**Итоговый ансамбль:**
```python
final_score = (1 - BETA) * (ease_knn_score) + BETA * als_score
```

где `BETA = 0.10` — вклад ALS.

**Метрика:** NDCG = 0.97040 (улучшение +0.00305 относительно чистой EASE)

**Почему ансамбль?** Разные модели ловят разные паттерны:
- EASE — глобальные item-item связи
- KNN — локальные похожести
- ALS — латентные факторы пользователей и треков

---

### 🔹 Шаг 5: Нормализация скоринга
Перед объединением в ансамбль все скоры приводятся к единому масштабу:
```python
def standardize(x):
    return (x - mean(x)) / std(x)
```
Это критично, иначе модель с бóльшими значениями доминирует в ансамбле независимо от качества.
